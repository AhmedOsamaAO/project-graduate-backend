# Domain documentation

- This backend has one domain context.
- Read root `CONTEXT.md`, when present, for canonical terminology.
- Read relevant decisions under `docs/adr/` before changing an affected area.
- Use glossary terminology in code, issues, and discussions.
- Surface conflicts with existing architectural decisions explicitly.
- Create glossary entries and ADRs when terms or significant decisions are settled; missing files do not block exploration.
- Keep `CONTEXT.md` a domain glossary, free of implementation details.
- `MVP.md` defines approved product scope; `schema.md` is the original DBML design. Neither establishes what is already implemented.
